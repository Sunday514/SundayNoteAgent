# 知识库规则

## 目标

- 维护可信、低摩擦、低熵的个人知识库，保留能改善检索、回答或判断的知识增量。
- 先依据目标、事实、约束和因果关系分析，再用已有框架对照；保留有依据的新关系和解释。
- 价值判断依据已确认的个人取舍，区分事实、推断和价值前提，明确表达结论；主流立场和共识不自动成为价值结论。

## 分层与权限

- `.import_files/`：原始文件、解析产物和临时日志，由导入流程管理。
- `10_原始材料/`：外部资料的忠实总结，默认只读。
- `20_每日记录/`、`21_每周记录/`、`22_每月记录/`、`23_项目复盘/`：个人活动和项目记录。写入前确认操作和全部目标；用户已明确指定时直接执行，新增目标或操作再确认。
- `30_知识库/`：稳定、可复用的 Wiki，默认检索入口，按 Skill 维护。
- `40_个人写作/`：个人表达，仅在用户明确要求时读写。
- Schema：规则、配置、模板和工具，仅在用户要求维护时修改。
- 保留各 Skill 对删除、归档、未确认结论和个人上下文草案的专门确认要求。

## 知识维护

- Raw 和 Routine 是并列证据。忠实总结留在 Raw，提炼的关系、方法、适用条件和稳定判断进入 Wiki。
- 优先局部更新同主题页面并保留人工内容；独立、稳定的主题才新建。当天流水、一次性安排、未验证猜测、原样摘录和命令输出不进入 Wiki。
- Wiki 在相关判断、方法和限制附近保留实际来源 wikilink，header `sources` 汇总页面来源；不确定内容明确标记。
- 每份长期 Raw 应由相关 Wiki 承接；Routine 只链接实际支撑稳定知识的记录。
- `30_知识库/索引.md` 组织核心 Wiki，不枚举全部来源。
- `30_知识库/知识库维护日志.md` 记录新页创建；实际全库维护由主 Agent 在整轮结束后记录一次。

## 表达

- 直接回答问题或说明实际结果，再提供理解结论所需的依据与限制；只呈现影响回答的事实、推断和价值前提。
- 用段落组织同一观点；并列、步骤或比较需要时使用列表或表格，标题说明具体内容。
- 省略开场包装、重复总结和无内容栏目。保留必要术语、公式、来源及产物约定字段；用户指定格式和解释深度时按其要求交付。

## 格式与托管

- 日期使用 `YYYY-MM-DD`，Daily 文件名使用 `YYYY-MM-DD.md`。
- 长期图像放在 `assets/figures/`，临时图片放在 `.import_files/`；Markdown 使用相对路径，默认显示宽度 640。
- 行内公式使用 `$...$`，块级公式使用独立的 `$$...$$`。
- `.obsidian/` 仅由安装器按所选模板模式维护 Calendar 和 QuickAdd 的项目字段；其他设置、会话、workspace、设备路径、环境变量和代理属于本地状态。
- 根规则、已安装工具和托管模板修改对应的 `SundayNoteAgent/` 源文件后，通过安装器刷新。
