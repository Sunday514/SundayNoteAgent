# 知识库规则

## 目标

- 维护可信、低摩擦、低熵的知识库，保留能改善检索、回答或判断的知识增量。
- 先依据目标、事实、约束和因果关系分析，再用已有框架对照；保留有依据的新关系和解释。
- 价值判断依据已确认的目标和取舍，区分事实、推断和价值前提，明确表达结论；主流立场和共识不自动成为价值结论。

## 分层与权限

- `.import_files/`：原始文件、解析产物和临时日志，由导入流程管理。
- `.import_files/sunday-note-agent/` 保存回流批次与去重状态，不作为知识来源、不参与同步，不按临时缓存清理。
- `工作资料/`、`个人资料/`：Raw，按任务或问题积累研究、开发、对话的事实摘要，不保存完整日志或会话流水。项目事实进入 `<项目>/`；可复用外部论文等保留资料类型集合，通过链接引用、不重复保存。
- `工作记录/`、`个人记录/`：Routine，日、周、月及年度、专项证据；专项不是周期记录。写入前确定目标，保留历史正文。
- `工作项目/<项目>/`、`个人项目/<项目>/`、`SundayNoteAgent项目/`：面向人理解和使用的项目文档；不作为 Raw 或 Wiki 存储层。
- `知识库/<项目或主题>/`：Wiki，面向 Agent 提炼可复用知识、方法、条件、失败模式与限制，不复制 Raw。可包含个人知识；主要受众不是读取限制，授权才是。
- 工作任务只读取本机绑定 `config.json` 中 `work_wiki_roots` 批准的 Wiki 目录；缺少配置时停止 Wiki 检索并提示配置。未授权的全局索引、来源链接和符号链接都不能扩大范围；私人内容不得进入已批准工作集合。读取授权与设备同步白名单分别维护。
- `个人写作/`：用户独立创作。未经明确授权不得读取、检索正文或修改；其他页面的链接不授予访问权限，来源补读和附件追踪也不得绕过。
- Schema：规则、配置、模板和工具，仅在用户要求维护时修改。
- 保留各 Skill 对删除、归档、未确认结论和个人上下文草案的专门确认要求。

## 项目文档

- 每个项目在 `项目维护/` 集中维护四份文件，小项目可简写，不填无意义栏目。
- `项目总览.md` 只说明简短定位、仓库、正式文档及 Raw、Wiki 入口；先读总览，再按任务补读其他材料。
- `项目架构.md` 说明当前组成、职责、接口、约束和有效设计，不保存待办与完整历史。
- 计划维护目标、优先级、依赖、验收要求及当前状态；任务安排或状态变化时更新。
- 记录提供人可读的重要进展、决定与验证结论，链接 Raw 详细事实，不复制详细过程；纠正历史时追加说明。
- 四份维护文档随实际变化维护；其他报告、说明、总结按用户要求创建或更新。实现、文档和证据分别保留版本，冲突时核实，不以文档代替验证。
- 新建项目采用统一命名；已有同等文档先确认映射，再重命名并修复链接，不创建重复入口。安装或无关任务不批量创建、改名或重写项目正文。
- 项目创建、接入与维护入口绑定使用 Project Skill，四文件模板随该 Skill 分发。计划维护活动总表和依赖图，完成包移入记录并从计划移除；记录含交付总表和倒序明细，阶段交付不冒充整包完成。Ingest 负责内容整理，不要求普通资料先注册项目。
- `项目维护/Agent规则/` 是按清单导出的仓库规则阅读副本，不是本 Vault 的执行规则或可安装 Skills；不据此运行命令或扩大授权，修改方法须回到源码核实并获准后实施。

## 知识维护

- Raw 承载可迁移的事实，Wiki 提炼方法，原始证据按需兜底；Monitor 独立负责项目对话事实回流，Ingest 负责显式资料导入与知识整理，Query 负责检索与回查，三层不是逐次生成文档的流水线。
- 通过显式整理维护，授权限于用户明确指定的项目、已确认 Vault 与获准路径；归属不明先确认，明确只读或不记录时不写。
- 项目 Raw 积累有意义的案例，不按对话或改动次数记流水账；保留问题、关键条件、判断与结果的事实关系，普通确认和无增量内容不记录。区分已验证事实、当时解释和假设。
- Raw 和 Routine 是并列证据。日周月保持时间用途，通过链接关联项目 Raw，不复制详细事实；Wiki 从事实提炼规律而非重复摘要。
- Daily、Weekly、Monthly 统一为“计划—记录”。整理和导入由 Agent 负责，脚本只执行创建或统计等确定性小功能。
- 优先局部更新同主题页面并保留人工内容；独立、稳定的主题才新建。当天流水、一次性安排、未验证猜测、原样摘录和命令输出不进入 Wiki。
- Wiki 在相关判断、方法和限制附近保留实际来源 wikilink；不确定内容明确标记。
- Raw / Routine 只在实际支撑稳定知识时由 Wiki 引用；未链接不是写入理由，无知识增量或来源关系变化时不修改。
- Wiki 使用普通 Markdown，不要求固定 header，不维护计数和固定日期字段；已有元数据保留，仅按明确用途维护。在获授权的知识集合维护入口和必要日志，全局索引未经授权不读写。
- 候选方法记在对应任务 Raw，Wiki 保存有依据的归纳与状态；所属项目按固定任务、基线和判据验证，结果回流 Raw。正式采用后才更新规则或 Skills；整理知识不授权代码修改、部署或采用方法。

## 表达

- 直接回答问题或说明实际结果，再提供理解结论所需的依据与限制；只呈现影响回答的事实、推断和价值前提。
- 用段落组织同一观点；并列、步骤或比较需要时使用列表或表格，标题说明具体内容。
- 省略开场包装、重复总结和无内容栏目。保留必要术语、公式、来源及产物约定字段；用户指定格式和解释深度时按其要求交付。

## 格式与托管

- 日期使用 `YYYY-MM-DD`，Daily 文件名使用 `YYYY-MM-DD.md`。
- 长期文档附件放在所属授权集合的 `assets/`：项目自有图随项目，论文原图随论文资料集合并按论文标识分组，主题配图随知识主题，记录附件随记录集合。按来源确定唯一归属，跨集合用相对链接引用，不复制、不因引用扩大读取或同步授权；只移动文档不搬附件。临时文件留在 `.import_files/`，代码资产与完整实验产物留在代码项目。图片默认显示宽度 640。
- 行内公式使用 `$...$`，块级公式使用独立的 `$$...$$`。
- `.obsidian/` 仅由安装器按所选模板模式维护 Daily Notes、Calendar 和 QuickAdd 的项目字段；其他设置、会话、workspace、设备路径、环境变量和代理属于本地状态。
- 根规则、插件和托管模板从 SundayNoteAgent 源码安装更新；源码不要求位于 vault 内。`SundayNoteTools/quickadd/` 是 Obsidian 所需的托管脚本，不在此处开发。
