# Lint

## 工作流

1. 列出 `30_知识库/` 全部 Markdown 并记录总数；维护日志只检查结构。
2. 运行 `scripts/lint_headers.py` 和 `scripts/audit_reachability.py`，保存全部 Wiki header、导航及 Raw / Routine 链接的机械诊断基线。
3. 逐页核读 Wiki，按需读取直接相关的 Raw / Routine；可按批次委派只读审计。每页记录无需修改、需要维护或 blocked，脚本不能替代正文检查。
4. 统一判断主题重复与边界、拆分合并、矛盾与过期结论、来源承接、核心导航和实质提炼。机械问题只报告，不生成写入任务。
5. 建立唯一全局计划，按下方字段保留完整任务。向用户展示维护范围和预期结果摘要后继续执行；计划不再新增任务，新发现留到最终报告。
6. 所有计划内 Wiki 写入交给 subagent，明确已授权操作和文件范围。动作、证据边界、验证方式相同且文件不冲突的任务可合并；主 Agent 逐项复核 diff、验证并更新状态。
7. 结束后重跑完整机械检查，确认每页有结论。报告覆盖数、实际修改、验证结果及未解决问题；披露阻塞原因、失败、未完成任务、计划外发现和机械诊断，合并重复状态、省略空类别。
8. 主 Agent 对整轮实际知识维护只写一次日志，记录完成结果、与计划的必要差异及最终验证；没有知识维护则不写。

## 边界

- 用户要求只读或禁止写入时，完成审计和计划摘要即结束，不委派执行、不修改文件、不写日志。
- 默认调用授权计划内知识维护。不确定结论、删除、归档、个人上下文或目标页不明确的任务标为 blocked，继续其他任务。
- Raw / Routine 仅作证据，Journal / Schema 不进入普通维护。
- 排版、header 格式、标点、局部润色和无语义影响的链接写法只报告；改变知识含义或破坏证据链的问题按知识维护处理。
- `wiki_unreachable` 通过 Wiki 导航处理，Raw / Routine 不加入 index。
- `raw_unlinked` 仅作为来源检查线索；有稳定知识增量或必要来源关系变化时才列入写入计划，否则记录无需修改。来源文件保持不变。
- 主 Agent 负责覆盖、审计、计划、调度、复核、报告和日志，不执行计划内 Wiki 写入。subagent 只改任务文件，不写日志；同一文件不得同时分派给多个未完成任务。
- 机械诊断、blocked、未执行任务和无变化页面不写维护日志。

## 执行计划

完整计划保留在本轮上下文或临时产物中，供执行、复核和按需展示；不写入 Wiki 正文。全局计划与子任务使用相同字段：

```text
任务（ID 与知识问题）：
目标与证据文件：
操作与授权边界：
执行者与依赖：
验收与状态：
```
