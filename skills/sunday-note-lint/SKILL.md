# Lint

## 工作流

1. 确认 Vault、模式和范围。工作 Wiki 限于本机 `work_wiki_roots`；未配置先提示，不遍历正文猜测归属。列出获准页面，记录覆盖数。
2. 读取范围内每页正文，按需追溯 Raw / Routine，检查重复、主题边界、矛盾、过期结论、来源承接和知识增量。逐页记录无需修改、待维护或证据不足；不以标题或机械检查代替阅读。
3. 有获准导航入口时运行 `scripts/audit_reachability.py`，显式传入模式与 Wiki、Raw、Routine scope。没有入口则报告导航覆盖限制，不借用未授权索引。断链、不可达和未承接来源只是线索，不能直接决定新增知识。
4. 写入前汇总一份计划：知识问题、目标与证据、操作、依赖和验收。计划留在对话或临时文件，展示范围与预期结果后执行已授权项；不确定结论、删除、归档和目标不明的事项先确认。
5. 按计划维护并检查 diff、证据及受影响链接。报告覆盖、实际修改和未解决事项；计划外发现另列，不扩散改动。实际完成知识维护时只记一次结果日志，未修改则不记。

## 边界

- 只读请求不写文件；普通调用授权计划内的 Wiki 维护，不授权修改 Raw、Routine、个人上下文、Journal 或 Schema。
- 工作任务不读取个人来源或未批准 Wiki；`个人写作/` 必须明确授权。链接、索引和符号链接不能扩大权限，读取许可不等于同步许可。
- 不检查或补齐固定 header，不维护计数，不为排版、标点或等价链接风格改写页面。已有元数据保持原样，除非用户要求或实际工具消费需要。
- 导航仅索引 Wiki；Raw / Routine 保持原位。有稳定增量或必要来源关系变化才整理知识，不以未链接为由逐篇导入。
- Lint 不替代项目验收；未读完或证据不足的范围明确披露，不声明完成。
