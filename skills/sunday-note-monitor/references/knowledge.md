# 知识与资料

识别值得长期保留的知识增量，以及能直接推进当前问题的资料。不是每轮都推荐论文，也不把普通开发进度转成 Wiki。

## 知识增量

1. 从原会话找候选：经过验证的因果解释、失败与修复揭示的边界、可复用方法、改变既有判断的证据。明确区分已验证结论与工作假设。
2. 通过给定 Query/Wiki 入口查现有同主题内容，再读必要的直接来源，确认是否已经收录、结论冲突或仅缺适用条件。不要只根据标题认定有缺口。
3. 判断是否值得沉淀：是否能改善后续检索、判断或重复任务；相较已有记录新增了什么关系、条件或证据。普通常识、容易直接查到的操作说明、一次性安排、原样日志和未验证猜测不推荐入库。
4. 有价值时给出精炼知识点、适用边界、证据和已有承接页面；没有合适页面可说明主题，但不创建页面或改写正文。

## 资料推荐

仅针对用户明确关注的方向或当前未解决的问题查资料，不因偶然提到某个词就推断新兴趣。先核对已有来源和近期推荐，避免重复。

确有缺口再检索外部资料，实际打开候选来源，优先论文原文、官方实现或有具体实验与经验的技术文章。核对日期、结论适用范围和证据强度，区分作者主张、实验结果与自己的迁移推断；不能只看搜索摘要就推荐。

说明“它能帮助解决哪个问题、值得读哪部分、相较已有材料新增什么”，附实际查阅的链接。相关但没有明显新增价值时不输出；不修改个人偏好、阅读计划或自动执行知识入库。
