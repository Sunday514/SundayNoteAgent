# 关联一致性

查找主任务未顾及的关联背景、下游影响和代码—文档冲突，不重新执行整个主任务。

## 检查方法

1. 从请求、回复、涉及文件及项目上下文提取本轮实际改变的接口、默认值、状态行为或设计决定，区分用户决定、主任务声明和已验证事实。
2. 阅读对应实现及直接消费者：调用入口、配置与安装导出、相关测试、设计和使用说明。选择会受该变化影响的关系，不因同名关键词扩展到无关模块。
3. 逐项对照有实际影响的契约：调用方是否仍使用旧接口，配置默认值是否与实现一致，部署副本是否有明确刷新流程，状态和产物是否被下游正确理解，文档是否指导了错误操作。不要将未要求部署的源码修改直接判为部署遗漏。
4. 需要历史设计依据时，从提供的 Query/Wiki 入口检索，再读直接支撑结论的来源及后续决定。核对文档适用版本、时间与权威范围；文档不是天然高于当前已确认需求。
5. 查找反证和已说明的限制。主任务已列出的待办不再提醒，除非发现其未考虑的新影响；暂时找不到测试或文档，不等于它不存在或必须新增。

## 交接标准

冲突要并列给出两侧证据，说明会误导什么操作或破坏哪个消费者，并区分“实现偏离已确认契约”“文档已过时”“意图不足，待确认”。背景遗漏则指出被忽略的材料如何改变当前判断，不能只列相关文件。

无实际行为或决策影响的措辞补全不推送。复杂架构判断证据不足时保留为具体疑问，不直接宣布设计错误；不自动更新正文、元数据计数或项目决定。
