# Query

先判断已有上下文是否足够；历史知识可能改变当前方案、重复故障诊断或高成本实验安排时才检索，简单明确的局部操作直接完成。项目入口未知时按需读取 `项目维护/项目总览.md`，不默认通读四份项目文档或整页 Wiki。当前会话已读且适用条件未变的内容直接复用，不创建或修改文档。

1. 确认目标 Vault、任务范围与环境授权，使用环境提供的搜索和读取工具。工作任务不补读个人来源，文件可见不等于获准；范围不明先确认，不读取正文猜测归属。未经明确授权不读取或修改 `个人写作/`，链接、索引和符号链接不扩大权限。
2. 已有获准入口时直接读取；否则按问题在获准范围内搜索路径、标题和关键词，再读取候选正文。工具不可用或拒绝访问时说明限制，不绕过权限或自动安装依赖。
3. 检索按路径、标题和正文匹配，不要求 header。先定位标题和相关小节，只读解决当前疑点所需内容；证据足够或没有相关候选时停止，不递归展开引用。候选命中不等于已读取证据。
4. 事实优先从 Raw 获取，方法与判断条件从 Wiki 获取。使用方法前对照当前输入、环境与约束判断适用性，不适用则不套用。方法条件不清、证据冲突或需核验具体事实时，按明确入口补读获授权的资料、项目记录和时间记录（包含年度、专项）；不把 Wiki 缺页当作没有证据。不默认寻找原始 Agent 轨迹；仅在事实冲突、关键细节缺失或明确要求精确复核时，自行尝试定位获准的本机记录。异机可能没有对应记录，找不到就说明限制，不否定已有 Raw。个人可引用工作，工作不补读个人；不递归追踪链接。
5. 只输出当前问题或决策需要的方法、条件和必要来源，不复制长篇检索结果；知识不可达时说明影响，继续可独立开展的工作。依据实际读取内容回答，不复述来源结构，不展示 `%% agent ... %%`。仅在诊断需要或用户要求时说明候选筛选过程；不推断未确认的个人偏好或计划。

全程只读，不修改知识文件或运行状态，不自动触发 Ingest、Lint 或 Audit。产生稳定新知识时只提出写入建议。
