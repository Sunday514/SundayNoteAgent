# Query

项目任务先读 `项目维护/项目总览.md`，按问题定位架构、计划、记录及资料层 Raw、集中 Wiki 的入口，不创建或修改文档。

1. 确认 Vault 与任务模式。工作请求只使用工作来源及本机配置 `work_wiki_roots` 批准的 Wiki 目录；缺少授权先提示配置，不遍历 Wiki、不读取未批准的全局索引。个人任务按需读取 `个人记录/个人上下文.md`；未经明确授权不得检索、读取 `个人写作/`。准确路径、来源链接和符号链接也不能扩大权限。
2. 已有获准入口时直接读取；否则提取 3–8 个线索，运行 `scripts/query_search.py --vault-root <vault> --mode work|personal <关键词...>`。默认从本机绑定读取模式，未绑定时安全默认 work。只检索 `知识库/` 中获准目录，具体项目由总览链接定位。
3. 检索按路径、标题和正文匹配，不要求 header。从候选中先读最相关的页面，证据足够时停止；候选命中不等于已读取证据。
4. 事实优先从 Raw 获取，方法与判断条件从 Wiki 获取。需要细节时按明确入口补读获授权的资料、项目记录和时间记录（包含年度、专项）；不把 Wiki 缺页当作没有证据。不默认寻找原始 Agent 轨迹；仅在事实冲突、关键细节缺失或明确要求精确复核时，自行尝试定位获准的本机记录。异机可能没有对应记录，找不到就说明限制，不否定已有 Raw。个人可引用工作，工作不补读个人；不递归追踪链接。
5. 依据实际读取内容回答并保留相关证据，不复述来源结构，不展示 `%% agent ... %%`。仅在诊断需要或用户要求时说明候选筛选过程；不推断未确认的个人偏好或计划。

全程只读，不修改知识文件或运行状态，不自动触发 Ingest、Lint 或 Audit。产生稳定新知识时只提出写入建议。
